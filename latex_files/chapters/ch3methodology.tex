\section{High level architecture}
Nodes are organized into Kademlia binary tree. Each node has a 256-bit ID to prevent collision. When a client wants to find a torrent, it uses the infohash as the key to traverse through the network.
For each hop, the distance is computed using XOR, and the client will iteratively choose nodes that are closer to the key.
Once it obtain a list of peers participating in the desired torrent, it makes TCP connections to these peers to obtain piece availability. It then finally pull these nodes.
While it is participating in the torrent swarm, it may also communicate with other peers to discover more peers.

\section{Implementation}
The implementation of this project will use three algorithms: multicast, resource discovery, and replication \& consistency protocols.
We will use Kademlia DHT and multicast as part of resource discovery. Replication \& consistency protocols are part of the piece exchange operations.
The programming language of choice is Python.

\section{Deployment}
To deploy the project, we will use a mix of cloud instances (such as AWS EC2) and virtual machines to simulate multiple entities in the distributed system.
For a small scale demonstration, we will use 50 entities, acting as DHT nodes and peers. There will be two seeders to start with.
